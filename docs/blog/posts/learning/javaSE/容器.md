选择集合时，先描述数据的关系：需要按位置访问、需要去重、需要键值查询，还是需要从两端取放？语义确定之后，再讨论具体实现与复杂度，通常会更清楚。

## 一张选择表

| 需求 | 常用选择 | 需要知道的边界 |
| --- | --- | --- |
| 按加入顺序存储，允许重复 | `ArrayList` | 索引访问 O(1)，中间插入或删除通常 O(n) |
| 去重，不要求遍历顺序 | `HashSet` | 合理哈希分布下，查找与添加期望 O(1) |
| 去重，同时保留插入顺序 | `LinkedHashSet` | 维护额外的顺序信息 |
| 根据键查询值 | `HashMap` | 不保证遍历顺序，键需要稳定的相等性规则 |
| 根据键查询，并保留插入顺序 | `LinkedHashMap` | 也可以配置为按访问顺序维护 |
| 按键排序或做范围查询 | `TreeMap` | 主要操作 O(log n)，比较规则要符合预期 |
| 作为栈或队列 | `ArrayDeque` | 两端操作摊还 O(1)，不允许 `null` |

`Map` 不属于 `Collection` 的子接口。`List`、`Set`、`Queue` 则属于 `Collection` 体系。

`LinkedList` 虽然能以 O(1) 修改已定位节点附近的链接，但通过索引找到那个节点仍需要遍历；“链表插入快”不代表任意按索引插入都快。

## 小例子：保序去重与词频统计

下面的代码可以保存为 `CollectionsDemo.java`，使用 Java 17 执行 `java CollectionsDemo.java`。

```java
import java.util.ArrayList;
import java.util.LinkedHashMap;
import java.util.LinkedHashSet;
import java.util.List;
import java.util.Map;

public class CollectionsDemo {
    public static void main(String[] args) {
        List<String> words = List.of("java", "spring", "java", "vue");

        List<String> unique = new ArrayList<>(new LinkedHashSet<>(words));
        System.out.println(unique); // [java, spring, vue]

        Map<String, Integer> frequency = new LinkedHashMap<>();
        for (String word : words) {
            frequency.merge(word, 1, Integer::sum);
        }
        System.out.println(frequency); // {java=2, spring=1, vue=1}

        List<String> editable = new ArrayList<>(words);
        editable.removeIf(word -> word.equals("java"));
        System.out.println(editable); // [spring, vue]
    }
}
```

这里刻意使用有顺序保证的实现，所以输出顺序是可解释的。不要让业务逻辑依赖 `HashMap` 恰好展示出来的某个顺序。

## HashMap 的键为什么不应随便修改

哈希集合先通过哈希信息定位，再通过相等性比较确认目标。如果键加入后，参与 `equals` 或 `hashCode` 的字段改变了，后续查找可能无法在预期位置找到它。

常用做法是使用不可变的标识作为键，例如用户 ID 或不可变值对象。使用自定义键时，`equals` 与 `hashCode` 必须表达同一套身份规则。

`HashMap` 可以有一个 `null` 键，也可以有 `null` 值；但很多其他实现没有这项约定。例如 `ConcurrentHashMap` 不允许 `null` 键或值，不能只看它们都实现 `Map` 就假定行为相同。

## 遍历时删除：让迭代器知道变化

在增强 `for` 循环中直接调用列表的 `remove`，可能触发 `ConcurrentModificationException`。这是尽力而为的错误检测机制，不是线程安全保证，也不应当依赖它总会抛出异常。

筛选删除可以使用 `removeIf`。需要更细的遍历控制时，使用迭代器自己的 `remove`：

```java
var iterator = editable.iterator();
while (iterator.hasNext()) {
    if (iterator.next().isBlank()) {
        iterator.remove();
    }
}
```

是否支持删除还取决于集合实现；不可修改集合的迭代器也不支持 `remove`。

## 三种容易混淆的“不能修改”

- `List.of(...)`：不可修改，不允许 `null` 元素。
- `Arrays.asList(array)`：长度固定，可以 `set`，但不支持改变长度的 `add` 和 `remove`；与原数组共享存储。
- `Collections.unmodifiableList(list)`：不可修改的视图，原列表变化仍可能通过视图反映出来。

需要独立快照时，可以考虑 `List.copyOf(list)`。它不允许 `null` 元素，也不会深拷贝元素对象。

## 并发集合仍然需要理解操作边界

`ArrayList` 和 `HashMap` 不提供并发修改的线程安全保证。`ConcurrentHashMap` 支持并发操作，但先 `get` 再 `put` 是两次独立操作，不会自动变成原子更新。

计数可以按需求考虑 `merge` 或 `compute` 等方法。跨多个键、多个集合或外部系统的约束，还需要额外设计一致性边界。

## 练习：让数据结构解释你的选择

1. 保存最近打开的页面，要求去重并更新访问顺序，会选择哪个集合？
2. 为什么 `HashSet` 可以判断重复，却不适合用来表达排名？
3. 如果词频统计允许多个线程同时更新，原来的循环有哪些问题？
